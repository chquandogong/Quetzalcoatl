# 자율 실행과 안전 게이트 (§1.6 · §18 · §19 · §20 · §21 · §24)

> 정본: `SKILL.md` §18 지속 자율 실행 · §19 회복력 · §20 Git · §21 핸드오프 · §24 `/context`.

## 한 줄

> 자율은 **승인된 계획 범위 안에서** "확인 질문"을 없애는 것이지, **안전 게이트**를 없애는 것이 아니다.

## 순서 (§18.1)

1. Intake → Office Hours → (필요시) Feasibility로 **의미와 방향을 한 번 합의**한다.
2. 사용자의 실행 지시("묻지 말고 끝까지", "자율로 진행")는 **명시적으로 위임한 범위에 한해** 계획 승인으로 본다.
3. 승인된 범위 안의 가역 작업은 확인 없이 완료까지 연속 실행한다. 모르는 것은 가정으로 적고(`ASSUMPTIONS`) 계속 간다.

## 허용목록 (§18.2 · C-19)

"되돌릴 수 있나?"를 압박 속에서 매번 판단하면 회색지대에서 실수가 난다. 자율 진입 시 **범위 안**(편집 경로 · 명령군 · 기존 remote로의 commit/push/tag — push·tag는 사용자 사전승인 시 · 일반 테스트 수단)과 **범위 밖**(§1.6에 해당하며 유효한 승인이 없는 행동 · 목록 밖 비가역·외부)을 목록으로 먼저 고정한다. 목록 밖이거나 §1.6에 해당하면서 유효한 승인이 없으면 자동 정지. **허용목록 초안은 에이전트가 쓸 수 있으나 등재만으로 승인이 생기지 않는다** — 사람의 승인·사전승인이 범위(대상·환경·행동·데이터·비용)를 포함할 때만 들어가고 근거를 적는다.

자율 수준: L0 신중 / L1 표준(기본) / L2 적극(사전승인 게이트 통과) / L3 완전(위임 범위 전부). L3도 위임 범위 안에서만이다.

## 연속 실행 루프 (§18.3)

대시보드에서 다음 미완료 작업 선택 → 허용목록 안 AND (게이트 비해당 OR 유효한 승인 있음)? → 아니오면 결정 대기에 적재·정지, 예면 의존 결정 미해결 여부 확인 → 실행 → 결과·가정·리스크 기록 → 의미 있는 단위마다 커밋 → 대시보드·미러 갱신 → 반복. 큐가 비거나 남은 일이 전부 게이트/차단이면 멈추고 사람에게 결정 묶음을 제시한다.

## 합리화 차단표 (§18.4) — 멈춰야 할 생각들

| 생각 | 현실 |
| --- | --- |
| "되돌릴 수 있는 일인데 확인받자" | 가정 적고 진행하라. 확인 질문이 자율의 적이다 |
| "자율 모드니 이 삭제/배포/발송도 그냥" | 게이트다. 허용목록·사전승인에 없으면 멈춘다 |

| "테스트가 녹색이고 봇도 승인했으니 검증 끝" | 그 결과는 검사한 범위까지만이다. 실제 경로의 관측 기록이 있어야 "검증됨" |
| "리뷰어가 응답이 없으니 승인으로 보고 진행" | 무응답·예산 소진은 승인이 아니다. 의존하는 출시만 차단, 독립 작업은 계속 |

## 정직성과 강제 바인딩 (§18.6 · §18.7)

자율 수준·허용목록은 **강제되는 락이 아니라 약속**이다. 최종 안전장치는 게이트·커밋 이력·사람의 검토다. 다만 실행 환경이 승인 훅 같은 강제 수단을 제공하면 핵심 **안전** 규율(게이트·체크포인트·하위 에이전트 범위)을 거기에 바인딩한다 — 환경에 있고 검증될 때만, "강제됨"을 확인 전에 가정하지 않으며, 루프 지속은 안전 속성이 아니므로 바인딩 대상이 아니다. 도구별 실현 수단은 본문이 아니라 [`CAPABILITY_MATRIX`](https://github.com/chquandogong/Quetzalcoatl/blob/main/docs/appendix/CAPABILITY_MATRIX.md)에 둔다.

## 회복력 (§19)

레이트리밋은 중단이 아니라 **대기 후 재개**. 체크포인트 = 마지막으로 성공한 커밋. 재개 전 이미 한 일인지 확인(중복 커밋·중복 발송 방지). **외부 발송·결제는 자동 재개 대상에서 제외.** 하위 에이전트의 제한·정지도 대시보드에 기록하고 재투입하거나 재개한다 — 조용히 버리지 않는다. 도구 없는 챗에서는 재개 지점을 대시보드·커밋에 남겨 사용자가 다음 메시지에서 이어가게 한다.

## Git (§20)

repo가 없으면 정규화한 프로젝트명으로 `git init`(기존·상위 repo가 있으면 확인). Conventional Commits, **의미 있는 단위마다** 커밋(마이크로스텝 금지), AI 작업엔 co-authored-by, 결정엔 결정 로그 참조. push는 허용된 경우에만, **새 공개 원격 생성은 게이트**, Ship 시 `vX.Y.Z` 주석 태그 — push·태그는 사전승인 범위 안에서만, 게시·배포를 유발하면 그 영향까지 승인.

## 핸드오프 (§21)

대시보드는 여러 에이전트·기기가 작업을 나눠·이어서 하게 하는 **공유 조정 상태**다. 동시성은 락이 아니라 커밋으로: 기본은 단일 라이터, 정말 병렬이 필요하면 commit-as-CAS(claim은 커밋이 remote에 안착했을 때만 확정, 충돌은 git 충돌로 표면화). 단일 진실 원천 = git repo, live artifact는 읽기 미러.

## `/context` (§24)

새 모델·에이전트 환경을 온보딩하기 위한 **벤더-중립 읽기 전용 스냅샷**(C-21). 기존 SSOT(브리프·대시보드·결정 로그·가정·git 로그)에서 뽑는 export이지 새 문서가 아니다. 외부에 붙여넣는 산출물이므로 비밀·토큰·PII·원문 로그는 제외하거나 요약한다. `/handoff`(보드 갱신, 진행 중 협업)와 구분된다.
