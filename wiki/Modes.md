# 모드 (§2) — v3.3.0

`/Quetzalcoatl` 하나가 전체 워크플로우를 켜는 **마스터 명령**이고, 아래 하위 모드는 그 안의 단계로 바로 들어가는 입구다. 모드는 Claude Code에 등록된 별도 슬래시 명령이 아니라 **스킬 본문 §2의 약속**이다 — 스킬이 켜진 세션에서 `/office-hours`처럼 쓰면 그 단계로 전환되고, 명령을 정확히 쓰지 않아도 의도가 비슷하면 적용된다.

| 모드 | 목적 |
| --- | --- |
| `/Quetzalcoatl` | **스킬 전체 호출 (마스터 모드).** 의미 검증부터 배포·회고까지 전 과정을 순서대로 적용한다 |
| `/office-hours` 또는 `GarryTan 오피스아워` | 아이디어를 압박 검토하고 진짜 문제와 최소 쐐기를 찾는다 |
| `/feasibility` | 가치·기술·비용·리스크 타당성을 검토한다 |
| `/alternatives` | 3~5개 대안을 만들고 기준표로 비교한다 |
| `/agent-team` | 하위 에이전트 역할을 나눠 조사·기획·설계·검토를 진행한다 |
| `/cross-check` | Claude와 GPT의 독립 검토를 비교하고 합성한다 |
| `/spec` | 모호한 의도를 실행 가능한 명세로 바꾼다 (§8.1) |
| `/plan` | 단계별 실행 계획을 만든다 (§8.2) |
| `/design-review` | 제품/UX/시스템 설계를 평가한다 — 규모 적합성 포함 (§9.2) |
| `/eng-review` | 아키텍처, 데이터 흐름, 테스트, 엣지 케이스를 검토한다 (§9.1) |
| `/risk-review` | 보안, 법률, 운영, 품질 리스크를 찾는다 |
| `/test-plan` | 테스트 계획과 합격 기준을 만든다 — 프로젝트성 작업에는 검증표(기능 지도)까지; 구동은 요청 범위·실행 조건이 있을 때 (§11 · C-29) |
| `/dashboard` | 진행·리스크·결정 대기를 대시보드화하고, 정본→보기 좋은 HTML 미러를 redeploy한다 (§7.2) |
| `/decision-log` | 결정 기록을 남긴다 (§6.3 · C-10) |
| `/report` | 종합 보고서를 설명층 마크다운으로 만든다 — 결론 먼저 · 쉬운 말 용어 · 근거 부록 · 기존 정본은 인용 (§6.3 · C-27) |
| `/present` | 발표 자료 세트를 만든다 — 대본(정본) · 상호작용 HTML 덱(기본) · 필요 시 pptx(노트에 대본 전문) · 요청 시 음성/영상 (§6.5 · C-28) |
| `/ship` | 배포 전 체크리스트와 릴리즈 판단을 만든다 (§12.1) |
| `/retro` | 회고, 배운 점, 다음 개선을 정리한다 (§12.2) |
| `/handoff` | 다른 에이전트·기기가 이어받게 핸드오프 보드(대시보드)를 갱신한다 (§21) |
| `/resume` | 마지막 커밋(체크포인트)에서 작업을 안전하게 재개한다 (§19) |
| `/autonomy` | 자율 수준(L0~L3)과 실행 허용목록을 설정한다 (§18) |
| `/context` | 프로젝트 목표·제약·현재 단계·열린 결정·최근 변경을 **벤더-중립 휴대용 브리핑**으로 합성한다 (§24) |

> 긴/복잡한 작업에서 사용자가 "묻지 말고 끝까지", "자율로 진행"이라고 하면 **§18 지속 자율 실행**이 켜진다 — 승인된 계획 범위 안에서 확인 질문 없이 실행하되, §1.6 안전 게이트는 유지한다.
