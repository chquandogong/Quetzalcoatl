# 교차검증 (§5)

> 정본: `SKILL.md` §5 Claude-GPT 교차검증 프로토콜 · 양식 C-7(브리프) · C-8(적대 검토 브리프) · C-9(통합 로그·원장).

## 언제 (§5.1)

진행 여부 · MVP 범위 · 아키텍처 · 중요한 문서 · 보안·법률·재무 판단 · 비용이 큰 선택 · 되돌리기 어려운 변경 · 사용자가 "교차검증", "둘 다", "더 확실히"라고 말할 때.

## 어떻게 (§5.2)

1. 두 모델에 **같은 브리프**를 준다. 서로의 답을 먼저 보여주지 않는다.
2. 각자 독립적으로 3~5개 대안과 추천안을 낸다. 그다음 서로의 답을 **비판**하게 한다.
3. 공통점·차이점·충돌·고유 통찰을 분리한다. 최종 판단은 "어느 모델이 말했는가"가 아니라 **근거와 검증 가능성**으로. 검증 불가능한 주장은 가정으로 표시한다.

### 라운드형 검토의 규율 (v3.3.0 — §5.2 8~10)

- **라운드 예산을 먼저 정하고 검토 범위를 기록한다.** 최초 독립 검토는 같은 전체 브리프로, 후속 교차 비판은 바뀐 부분·미해결 항목과 **그 영향을 받는 기존 규칙·양식**을 본다.
- **종결 상태는 수행 결과로 정한다**: 필수 범위 검토 완료 + 처리 합의 = 합의 / 검토 완료 후 이견 = 쟁점 잔존 / 필수 검토 미완 = 검토 미완료. **예산·시간 소진과 무응답은 합의·승인의 근거가 아니다.** 미해결 blocker 또는 필수 검토 미완료에 의존하는 실행·출시만 차단하고 독립 작업은 계속한다.
- **지적마다 원장을 남긴다**(C-9): ID · 심각도(blocker/should/nit) · 처리(수정 / 반박+근거 / 범위 밖·보류) · 재검증 결과. 루프를 끝내려고 동의하지 않는다.
- **지정한 검토 모델을 조용히 대체하지 않는다.** 다른 모델의 독립 검토를 확보했으면 실제 모델을 기록하고 지정 조건 충족 여부를 별도로 표시한다. 확보하지 못했을 때만 §5.6의 시뮬레이션으로 강등한다.

## 한 모델만 쓸 수 있을 때 (§5.6)

현재 모델이 1차 답을 만들고, 같은 모델 안에서 "다른 모델이라면 반박할 관점"을 시뮬레이션한 뒤, 결과에 반드시 **"실제 교차검증 아님"**이라고 표시한다. 가능하면 사용자가 나중에 다른 모델에 붙여넣을 검증 프롬프트를 준다.

## 이 저장소는 어떻게 하나 (dogfooding)

v1.4.1부터 **모든 릴리스를 실제 Claude↔GPT 교차검증**으로 닫는다. Claude가 변경을 저작하고 커밋한 직후, 로컬 Codex CLI(`codex exec`)에 **커밋 diff + 변경 후 본문 전문**을 첨부한 적대 검토 브리프를 넘긴다(웹·원격 조회 없이 첨부만으로 검토). v3.3.0은 처음으로 §5.2-8의 라운드 예산을 자기 자신에게 적용했다 — 4라운드(REJECT 94 → REJECT 93 → 검토 미완료 → 쟁점 잔존·blocker 0), 결함 29건 중 28건 반영. 3라운드의 "검토 미완료"는 저작자 브리프가 원지적을 빠뜨린 탓이었고, 예산 소진을 합의로 치환하지 않고 4라운드로 보완했다. 기록은 [`docs/02-decisions/CROSS_VALIDATION_LOG.md`](https://github.com/chquandogong/Quetzalcoatl/blob/main/docs/02-decisions/CROSS_VALIDATION_LOG.md).
