# 문서 체계 (§6 · §7)

> 정본: `SKILL.md` §6 문서화 프로토콜 · §7 대시보드 프로토콜. 문서는 결과물 더미가 아니라 **판단을 추적 가능하게** 만드는 체계다.

## 디렉터리 (§6.1)

```text
docs/
├── 00-overview/    PROJECT_BRIEF · DASHBOARD · REPORT · PRESENTATION
├── 01-discovery/   OFFICE_HOURS · FEASIBILITY_REPORT · RESEARCH_NOTES · ASSUMPTIONS
├── 02-decisions/   DECISION_LOG · ALTERNATIVES · CROSS_VALIDATION_LOG
├── 03-spec/        SPEC · ARCHITECTURE
├── 04-quality/     RISK_REGISTER · TEST_PLAN · VERIFY
├── 05-ops/         RUNBOOK · RETRO
├── appendix/       GLOSSARY · CONVENTIONS
└── assets/         다이어그램 · confirmed/(확인층 스냅샷) · deck/(덱·음성·영상 렌더)
```

작은 프로젝트는 루트에 평면 배치해도 되지만 **두 방식을 섞지 않는다.** 도구가 없으면 같은 이름의 마크다운을 텍스트로 출력한다.

## 작성 규칙 (§6.2)

- 설명층은 마크다운, 그림(Mermaid)·표 우선.
- **용어는 독자가 별도 조사 없이 이해되게** — 독자와 선수지식 범위를 명시하고 낯선 핵심 용어는 첫 등장에서 풀며 정의는 부록으로. 용어집이 있다는 것만으로 이해 가능성이 검증된 것은 아니다.
- **근거를 명시** — 외부 사실엔 출처(문서명·링크·확인일), 내부 측정·계산엔 기록·산식, 추정엔 가정, 목표값엔 목표 표시. 확보하지 못한 사실은 **미확인**(추정으로 바꾸지 않는다).
- 문서 머리에 상태/날짜/소유자. 규칙은 한 번 정하고 그대로.

## 산출물 3층 (§6.4 · C-26)

같은 내용도 읽는 쪽이 다르면 맞는 형식이 다르다. 층은 **필요할 때만** 더한다 — 기본은 설명층 하나.

| 층 | 읽는 쪽 | 형식 | 역할 |
| --- | --- | --- | --- |
| 확인층 | 고객·발주자·승인자 | 합의된 형식(워드프로세서 문서·PDF 등) | **승인 기준선** — 고객이 확인한 판을 그대로 보존 |
| 설명층 | 사람(팀·검토자·미래의 나) | 마크다운 + Mermaid·표 | 구성도·흐름도·근거·결정 |
| 기계층 | 프로그램·에이전트·CI | 스키마 있는 JSON/YAML(예: `task.json`) | 선언된 범위의 작업·상태·요구사항을 읽고 검증 |

규칙의 핵심: **정본은 층마다가 아니라 사실마다 하나**이고 범위를 선언한다. 확인층은 편집 정본이 아니라 **고객이 확인한 기준선**이며 바꾸지 않는다(확인 뒤 변경은 미확인 후보판). 고객 반환본은 입력이다. 층은 안정 ID + 원천 리비전 + 내용 대조로 잇고, 기계층은 스키마로 검증한다.

## 자립 자료 (§6.5 · C-27 · C-28)

공유되는 자료는 받은 사람이 발표자나 추가 조사 없이 이해할 수 있어야 한다. 종합 보고서(`REPORT.md`)는 결론 먼저 + 쉬운 말 용어·근거 부록이며 기존 정본을 인용·요약한다. 발표는 대본(`PRESENTATION.md`)이 정본이고 HTML 덱·pptx·음성·영상은 파생 렌더다. 음성·영상은 요청이 있을 때만, 합성 전 분량·비용을 사람에게 보여 확인한다 — 비용 한도는 외부 호출 승인을 대체하지 않는다.

## 대시보드 (§7 · C-11)

대시보드는 작업량이 아니라 **판단 가능성**을 보여준다: 현재 상태 · 목표 · 진행 · 작업 보드(claimable) · 재개 지점 · 결정 대기 · 가정 · 리스크 · 품질 지표 · 다음 액션 · 링크. 정본은 `DASHBOARD.md`(기계층이 관리하도록 선언된 보드 필드는 그 파일)이고, 보기 좋은 HTML 미러는 같은 URL에 redeploy하는 **읽기용 뷰**다. "자동 갱신"은 강제 락이 아니라 에이전트 규율이다.

## 이 저장소의 예

이 저장소의 `docs/`가 바로 이 체계로 스킬 자신의 개발을 기록한 것이다 — [docs/README](https://github.com/chquandogong/Quetzalcoatl/blob/main/docs/README.md). 결정은 D1~D18, 가정은 A1~A27, 교차검증은 사이클마다 한 절씩 쌓였다.
